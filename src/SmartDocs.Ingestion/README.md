# SmartDocs.Ingestion

Модуль загрузки, предобработки, разбиения на фрагменты (чанкинга) и векторизации документов для RAG-стека **SmartDocs**.

## Возможности

### 1. Предобработка и очистка текста (`SmartDocs.Ingestion.Preprocessing`)
Перед чанкингом текст проходит нормализацию через `IDocumentPreprocessor`:
* **Дедефисация (Dehyphenation)**: Автоматическое устранение переносов слов на стыках строк с учетом кириллицы и латиницы (например, `преобразова-\nтель` → `преобразователь`, `авто-\r\nматический` → `автоматический`), что критически важно для качества эмбеддингов.
* **Фильтрация пустых и служебных страниц**: Исключение пустых листов и страниц-заглушек технической документации («Для заметок», «Лист регистрации изменений», служебные штампы).
* **Очистка колонтитулов**: Удаление повторяющихся бегущих верхних и нижних колонтитулов и номеров страниц.
* **Схлопывание отточий**: Нормализация длинных цепочек точек в оглавлениях и спецификациях.
* **`PreprocessingChunker`**: Декоратор над любым чанкером, прозрачно применяющий препроцессинг перед нарезкой на чанки.

### 2. Стратегии чанкинга (`SmartDocs.Ingestion.Chunkers`)
* **`RecursiveCharacterChunker`**: Иерархический чанкинг по заголовкам Markdown, параграфам и предложениям с сохранением логической структуры текста.
* **`SentenceChunker`**: Чанкинг по границам предложений с поддержкой многоязычного Unicode (`\p{Lu}`).
* **`SemanticChunker`**: Семантическое разбиение на базе локальной ONNX модели BGE-M3 (вычисление косинусного сходства векторов предложений и разбиение в точках смены темы).
* **`CodeFileChunker`**: Синтаксический анализ исходного кода C# на базе Roslyn с сохранением объявлений `using`, пространств имен и контекста классов.
* **`TokenAwareChunker`**: Управление бюджетом токенов под целевую модель (TikToken / `ITokenCounter`). Поддерживает режим декоратора `IChunker`, автономный режим (`SplitIfNeeded`, `EnforceBudget`, `EnforceBudgetAsync`) и гарантирует, что ни один чанк не превысит заданный лимит токенов.
* **`ChunkingTokenBudgets`**: Двухуровневое бюджетирование токенов (`BaseTextBudget`, `ContextBudget`, `MultimodalBudget`, `FinalTargetCeiling`), исключающее переполнение контекста эмбеддингов после обогащения.
* **`ContextualChunker`**: Реализация Anthropic Contextual Retrieval — добавление сжатого контекста всего документа к каждому чанку через LLM.
* **`MultimodalChunker`**: Связывание текстовых чанков с описаниями извлеченных изображений (`ImageCaptioner`) и таблицами (`ExtractedTable`) с поддержкой интерфейса `IChunker` и встроенным контролем предельного размера токенов.
* **`FixedSizeChunker`**: Базовый чанкинг фиксированного размера с перекрытием (overlap).

### 3. Парсеры форматов (`SmartDocs.Ingestion.Parsers`)
* **PDF (`PdfDocumentParser`)**: Посимвольная реконструкция строк по координатам `BoundingBox.Bottom` библиотеки `PdfPig`, извлечение таблиц, диаграмм и растровых изображений.
* **Word DOCX (`DocxDocumentParser`)**: Парсинг структуры OpenXML, списков, таблиц в Markdown и медиафайлов (`word/media/`).
* **Excel XLSX (`XlsxDocumentParser`)**: Конвертация табличных листов в Markdown с сохранением столбцов и числовых форматов.
* **Markdown (`MarkdownDocumentParser`)**: Прямое извлечение секций, кода и таблиц.
* **`CompositeDocumentParser`**: Автоматический выбор парсера по расширению файла.

### 4. Конвейер индексации (`SmartDocs.Ingestion.Pipeline`)
* **`IngestionPipeline`**: Сквозной пайплайн, объединяющий парсинг документа, препроцессинг, чанкинг, генерацию эмбеддингов и сохранение в векторное хранилище `IVectorStore`.
